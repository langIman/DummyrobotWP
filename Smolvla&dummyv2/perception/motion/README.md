# DummyV2 MoveIt 安全适配层

本目录复用 `D:\DummyRobot_workplace\dummy_moveit_ws` 的机器人模型、SRDF、运动学配置和
MoveIt Servo，但不会修改该工作区，也不会启动其中的 `dummy_servo_hardware.py`。

## 控制链路

```text
浏览器 WASD / ↑↓ / 8426
        -> perception LiveControl
        -> 127.0.0.1:8801 MoveIt 安全网关
        -> MoveIt Servo 逆解
        -> perception 关节目标校验
        -> 127.0.0.1:8765 /motion
        -> DummyV2
```

ROS 网关不访问 USB。感知服务仍是唯一使用 8765 桥接的程序。

## 0.8.5 当前目标积分规则

取消相对反馈 6° 的目标超前限制及其超差重置；仅在关节行程边界缩放积分增量。
网关报告 `max_target_lead_deg=null`、`target_lead_limit_enabled=false`，
`joint_limit_limited` 专门表示行程边界缩放，不再混称 `lead_limited`。
感知服务同时取消 8° 目标角差拒绝，继续显示下发前的目标／反馈差值。
这不改变 Servo 的碰撞和关节速度检查，也不改变输入／反馈过期停止与松键重置。
下文较早版本的 6°／8° 说明仅作为历史记录。

## 一次性构建

在 ROS 2 Jazzy + MoveIt 2 可用的 WSL 发行版中执行（默认使用已恢复的
`SmolVLA-Lab-Recovered`，可用环境变量覆盖）：

```powershell
powershell -ExecutionPolicy Bypass -File .\motion\build_moveit.ps1
```

构建产物写入 `motion/.ros`，原 `dummy_moveit_ws` 不产生 `build`、`install` 或源码修改。

## 启动

先启动 MoveIt 网关：

```powershell
powershell -ExecutionPolicy Bypass -File .\motion\start_moveit.ps1
```

再启动感知服务并打开 `/collect`。页面只有在以下条件同时满足时才允许长按进入实机控制：

- MoveIt 安全网关协议匹配；
- 8765 DummyV2 桥接正常；
- 六轴由本感知服务成功使能；
- 实机关节反馈存在且不超过 500 ms；
- 没有预设运动、急停或原始命令占用。

## 安全行为

- MoveIt 网关启动后保持失能，不发送非零 Twist。
- 浏览器输入超过 350 ms 未更新时发送零速度；有已下发的目标时，用新鲜实机反馈发送一次保持目标。空闲不会自动失能。
- MoveIt 断线、目标异常或保持命令失败时执行急停。反馈过期、奇异/碰撞停止和 3 秒无运动进展先暂停；反馈不可用导致保持失败时升级急停。
- 每个 MoveIt 输出必须处于六轴软件限位内，且相对实机反馈的最大目标差不超过 8°。
- MoveIt 网关不执行原仓库中的启动使能、初始六轴速度或自动回位。
- 碰撞检查已打开；按用户此前要求取消有限条件数的奇异减速和停止，非法数值仍不得用于运动，详见下方历史说明。

## 0.8.18 当前坐标契约

所有平移、转向速度均在 `gripper_tool` 中解释：X 前、Y 左、Z 上。
W/S 为 ±X，A/D 为 ±Y，↑/↓ 为 ±Z；8/2 为绕 −/+Y，4/6 为绕 +/−Z。
每个网关周期使用最新关节反馈求出末端旋转矩阵 `R`，转换 `v_base=R v_tool`、
`omega_base=R omega_tool`；再以 105 mm 抓取点偏移做腕部速度补偿。
因此按住 W 并转向时，前进方向也随实际末端姿态改变。
`command_frame`、`translation_frame`、`rotation_frame` 都为 `gripper_tool`；
协议版本 7，拒绝历史版本。部署时须同时重启感知服务与网关。

## 0.8.17 坐标契约（历史）

平移和转向均使用固定 `base_link`。8/2 对应基座角速度 −/+Y，4/6 对应 +/−Z，
不乘夹爪朝向旋转矩阵。仍根据实时法兰姿态计算 105 mm TCP 杠杆补偿：
`v_flange = v_tcp - omega_base × r_tcp_base`，单独转向时保持估算抓取点。
健康检查与输入事件标明 `command_frame=base_translation_base_rotation`，
`translation_frame=base_link`、`rotation_frame=base_link`；协议版本 6。
感知服务拒绝旧协议或旧坐标契约，部署时须同时重启服务与网关。

## 0.8.3 控制契约（历史）

键盘平移使用固定 `base_link`，W/S 为 ±X、A/D 为 ±Y、↑/↓ 为 ±Z；不再随夹爪
旋转。鼠标角速度仍用工具坐标系旋转到基座，并保持原 TCP 杠杆补偿。
组合输入下，抓取点线速度使用固定基座分量，转向引起的腕部补偿单独叠加。
底座摆平时才等同于世界水平/竖直，不包含重力方向标定。

Servo 每 25 ms 输出 `/servo_node/joint_velocities` 的 `Float64MultiArray`，
单位 rad/s，顺序 `Joint1`～`Joint6`。网关按各轴方向转换为硬件 deg/s（不加位置偏置），
再连续累积成六轴位置。最新目标仍通过 `/trajectory` 返回；`POST /feedback` 同时返回
该快照，减少每周期一次 HTTP 往返。

协议版本 5，`output_mode=bounded_velocity_integration`、
`command_frame=base_translation_tool_rotation`；另报告
`translation_frame=base_link`、`rotation_frame=gripper_tool`。
`continuous_target.py` 将目标限制在最近真实反馈 ±6° 和硬件关节限位内，使用各轴
共同缩放系数，不储存被限幅的增量。源反馈继续以 5 Hz 采样，携带真实帧龄。
实际姿态在两次采样之间可能继续改变，±6° 不是对未测量瞬时姿态的误差保证。

速度输出中断超过 100 ms 时丢弃累积目标，不补发缺失时间的位移；新目标缺失超过
250 ms 时感知服务暂停。松键和各停止条件清除旧目标；重新按键从最新真实反馈起步。
真实碰撞检测与已有 8° 服务端检查保留。部署需同时重启感知服务和网关，无固件改动。

## 0.6.0 控制契约（历史，已由 0.8.0 替代）

Servo 当时每 40 ms 输出 `std_msgs/Float64MultiArray` 六轴位置，顺序为模型链的
`Joint1`～`Joint6`。此模式每步从实际反馈计算；不用从上一段命令状态继续积分的
`JointTrajectory` 滚动窗口，避免串口速度低于规划速度时目标持续超前。
当时网关协议版本为 3，健康检查报告 `output_mode=feedback_position_step` 及
`command_frame=gripper_tool`。感知服务拒绝旧基座坐标系网关，避免部署混用导致方向错乱。

进入控制时要求主控明确确认 `#CMDMODE 2`，使新目标可以替换前一个目标；
这只改变当前运行模式，不烧录固件。桥接收到完整运动确认后结束等待，不再固定占用
500 ms。六轴映射保持原有定义。0.6.1 的流式命令速度参数为 8，目标与实机反馈差
上限为 8°；回零、休止及准备位的预设动作仍使用速度 4。

进入控制的页面持有本次控制令牌，其他页面只能观察。服务端清理失效的输入和诊断；
松键与退出的并发请求不能让在途旧目标重新生效。保护暂停后需要先松开输入再继续。

离线闭环验收脚本 `verify_control_loop.py` 在独立 ROS domain 内运行实际 Servo、
网关与生产控制代码，机器人串口由假驱动替代。它检查 W/A、鼠标偏转、松键保持、
卡住不动时的目标差和暂停行为；不会连接 8765 或访问 USB。

## 0.6.1 速度和碰撞减速

- WASD 平移设定 0.10 m/s，鼠标最大转向 0.24 rad/s（约 13.8°/s）。网页显示当前值。
- 网关 HTTP 速度范围同步更新；输入目标频率在 0.7.2 提高至 25 Hz。
- 自碰撞预减速距离为 5 mm；环境物体预减速仍为 20 mm，碰撞检查和重叠停止有效。
- 8° 是目标相对实机反馈的最大偏差，不是每周期允许累计前进 8°。
- 隔离闭环测试还通过真实 HTTP 入口验证速度范围，并在独立 ROS domain 内加入

## 0.7.0 夹爪坐标系控制（历史，平移已由 0.8.3 替代）

工具 +X 前方、+Y 左方、+Z 上方对应 `link6_1_1` 的 -Y、+X、+Z。
证据为复制 URDF 的 J4→J5→J6 朝 -Y 延伸、J6 轴为 +Y；与用户“原 D 才向前”的观察相符。
这定义的是工具轴，不是相机图像轴。腕部相机若有安装滚转，两者不会自动一致。

网关每 20 ms 使用新鲜六轴实测反馈和原模型关节变换重新计算 FK，把工具 Twist
转换到 `base_link`，再交给原 Servo。没有累积鼠标角度来猜姿态，不改关节映射、
原仓库模型或固件。鼠标右移为工具 -Z 角速度，鼠标上移为工具 -Y 角速度。

`tool_frame.json` 的 `tcp_offset_in_link6_m` 是模型第六轴原点到抓取点的三维偏移，
单位米，**不是直接填安装端面到指尖的距离**，还需计入端面在模型中的位置。
未测量时保持零偏移及 `tcp_calibrated=false`，网页明确提示旋转围绕第六轴原点，
不声称指尖原地不动。取得尺寸后修正偏移并重启网关；不会做自动寻边运动。
转换使用 `v_flange = R_tool*v_tool - omega_base × R_link6*offset`，实现指定抓取点的转向补偿。
生产输入事件同时记录工具坐标系和 TCP 配置，便于解释采集数据。

`probe_tool_frame_offline.py` 在 ROS domain 197 验证两组姿态下 W、D、抬头和右转，
以 robot_state_publisher 的 TF 独立核对 FK；用虚拟 100 mm 偏移检查指尖旋转补偿。
虚拟偏移只存在于测试进程，不写入实机配置。测试报告在 `runtime/tool-frame-offline.json`。
传入 `--configured-tcp` 则离线验证当前配置的偏移，仍不会访问实机。

2026-09-16 用户粗测安装面至指尖约 105 mm，现采用 `[0, -0.105, 0]` 米补偿初值。
模型没有实物转接件；安装面暂假定与第六轴原点重合、横向偏移为零。配置保存测量值
和此假设，`tcp_configured=true`、`tcp_calibrated=false`；网页明确标注估算及待微调。
这不是对实物安装面位置或指尖保持误差的测量验证。
MoveIt 的 Twist 接口以规划坐标系接收，因此网关先转换到基座坐标系：
https://moveit.picknik.ai/main/doc/examples/realtime_servo/realtime_servo_tutorial.html

## 0.7.6 读取 5 Hz、目标下发 40 Hz

浏览器输入、感知服务输出、网关 Twist 和 Servo 发布周期改为 25 ms。
硬件反馈以 200 ms 为共享周期；松键保持需要即时采样，坏帧允许有界复核。
网关接受反馈 `age_ms` 并保留实际采样年龄，重复转发缓存不会延长 500 ms 看门狗。
读取低频会降低状态更新分辨率，不保证提高下发频率就一定更流畅。

以下为 0.7.2 的历史说明：

浏览器输入、Servo 输出、实机目标下发以及使能/录制时的六轴反馈，均设定为
40 ms 周期（25 Hz）。静止未使能时仍按需读角度。网页显示设定频率与最近 5 秒
实际成功读取/下发频率；空闲无运动时下发频率为 0，设定不等于实测保证。

桥接只对精确的 `#GETJPOS` 在收到完整换行、六个有限角度的回复后提前结束，
不会用裸 `ok`、半包或夹爪回复结束读取；100 ms 保留为异常读取等待上限。
串口仍串行互斥，不能并发读写抢回复。周期包含 HTTP/串口耗时，超时不补发积压目标。
速度、8° 目标差、反馈过期和急停保护不变。部署此更新需同时重启感知与 8765 桥接。

如果默认发行版不可用，可设置 `DUMMY_MOVEIT_WSL_DISTRO`；ROS 版本可用
`DUMMY_MOVEIT_ROS_DISTRO` 覆盖。启动前会检查对应的 `/opt/ros/<发行版>/setup.bash`。
原 `SmolVLA-Lab` 注册仍保留，但它当前仍引用旧路径；服务不会自动修改或注销它。

## 0.7.3 六轴反馈异常复核

相邻有效样本间隔不超过 0.5 秒时，使用 `max(8°, 2° + 360°/s × 间隔)`
作为宽松的反馈跳变检测范围（不是运动速度限制）。格式错误或越过该范围的回包
不会发布给网页、录制状态流或 MoveIt；立即再读，含首次最多三次。
复核期间不下发新运动目标、不失能；恢复可信反馈后继续正常控制。
三次均不可信则将反馈标为不可用，实机控制执行原有失败停止与失能流程。
异常复核的参考范围不会随重试时间扩大，连续错误不能靠等待自动被接受。

串口读取、反馈校验和状态发布保持顺序；运动发送获取同一串口锁后重新检查反馈，
避免等待通信时反馈变化造成校验失效。旧帧不会冒充带有新时间戳的正常帧。
异常回包、恢复事件、复核失败以及超过 8° 被拒的六轴目标和反馈，写入
`runtime/service.stderr.log`，录制中也写入事件流。正常帧不增加额外串口查询。
首次采样没有历史参考，超过 0.5 秒的正常采样间隔也不做短时跳变推断；
这一机制不是串口校验和，也不能保证识别所有数值看似合理的错误。
