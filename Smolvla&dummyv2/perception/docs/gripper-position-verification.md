# 夹爪位置命令核验（2026-09-15）

## 结论

实机主控支持位置控制 `!HAND_POS N`，N 为 0～100 的整数。用户依次定位全闭、全开后，已确认本次运行中的两端反馈约为 **-17.10615°（全闭）** 和 **-247.90343°（全开）**，角度跨度约 **230.79727°**，打开时角度减小。

因此当前默认 `HAND_POS 0～100` 与这台夹爪测量时的真实行程不对齐，也不能直接以 `N=100*开度` 控制。当前命令不能覆盖全行程；需要修正坐标映射或位置接口后，再做小范围位置跟随验证。本次没有改变主控或驱动板的零位、固件及参数。

**后续断电复测已确认角度基准不跨断电保持：夹爪保持全开不动，断总电后读数由 -247.90343° 变为 +22.09922°，约相差 270°，对应减速比 8 下的 6 圈电机转数。以下断电前两端绝对角度只作为历史测量，不能直接用于这次重启后的控制。**

通过已备份主控 Flash 的 Thumb 反汇编以及 ST-LINK HotPlug 读取运行内存，确认当前目标公式：

```text
target_angle = hand_min + float(N) * 2.3
当前 hand_min = -115°
N=0   → -115°
N=50  →    0°
N=100 → +115°（浮点运算有微小舍入）
```

这些是主控逻辑角度，不是夹爪开口的毫米值。位置调用使用固定速度参数 65；不能据此声称 65°/s，该参数未经物理速度验证。它没有使用网页的开合时长或 `!HAND_I` 电流变量。

## 保持全开时断总电复测

用户确认“断开总电源再上电，夹爪一直保持刚才全开”。重启后只发送只读 `#GETJPOS`，并使用 ST-LINK HotPlug 读取 RAM；没有发送运动、偏移设置或校准命令。

- 19:32～19:33 读取六轴：`[-1.37, -75.24, 180.66, 0.04, -0.27, 0.17]°`。
- 夹爪 `+0x08` 连续读取 `0x41B0CB33`，约 **+22.099218°**。
- 断电前同一全开位置约 -247.903427°，差值 +270.002645°。
- 主控夹爪减速比为 8，因此电机转一整圈对应逻辑角度 45°；差值约等于 6×45°。
- 开合电流变量由手工设置的 0.2 恢复成构造默认的 0.7，起点/另一端依然为 -115/+115。网页保存的 0.2 是服务设定，不能当成掉电后固件仍保持 0.2 的反馈。

这证明当前可见的夹爪角度不保留跨这次断总电的多圈位置，与仓库电机固件 `Motor::CloseLoopControlTick` 的“第一次按单圈编码器及 home offset 初始化，之后在 RAM 累计跨圈增量”实现吻合。驱动板本身的实机 Flash 未读出，因此不能把仓库实现与实机驱动固件宣称为逐字一致；但相同物理位置断电前后读数相差整圈已由本次试验直接观察到。

六轴主控运行内存中的 initPose 位于 `0x2000362C`，读到 `[0,-75,180,0,0,0]`。主控 MoveJoints 路径在发送前减去 initPose；对应源码反馈路径将驱动角度加上 initPose。启动只剩单圈位置时，六轴显示就会落在 initPose 附近，并不证明机械结构实际处于休止位。

位置目标仍是当前坐标系里的目标位置，而非每条命令增量。可靠使用需要固定已确认的上电物理姿态，或上电后重新建立参考/确定圈数。六轴应按已经定义的装配刻度姿态上电；夹爪可以考虑全闭作为易观察的启动参考，但还需验证该姿态的启动读数重复性。固定启动姿态本身不会修复 `!HAND_POS` 的默认端点映射。

本次第一次 USB 读取出现旧串口句柄的 `ClearCommError` 错误，桥接释放失效句柄后第二次只读查询成功。它没有阻止随后取得真实六轴回复；不能用第一次失败时的网页旧值作为启动读数。

## 开闭方向与校准限制

`!HAND_O` 给开合电流取负号，`!HAND_C` 使用正号，两者调用 CAN 电流设定。近期人工操作日志中，闭合操作后的后续反馈从约 -196° 到 -149°、再到 -110°，与“角度增大趋向闭合”的解释相符。但回复里的角度更新可能滞后，方向仍需与实际夹爪观察一起确认。

`!HAND_ZERO` 的流程包含：向存储起点发送速度参数 7 的位置目标，等待约 900 ms，设置电机偏移、请求反馈，等待约 100 ms，更新起点；再向存储另一端运动并等待、更新另一端，随后失能。该主控分支中未见检测夹爪接触/堵转后再确认物理端点的循环，不能当作已经验证的自动寻边标定。

尤其是校准改变起点后，`!HAND_POS` 仍使用固定 230° 总跨度。不得仅因存在 `HAND_ZERO` 命令就直接执行全行程校准。
