## 实机指令链路

| 地址 | 从实机二进制确认的行为 |
| --- | --- |
| `0x08012798` | 按对象 `+0xDD` 选择命令模式，值 2 进入可中断目标路径 |
| `0x08012A50` | 解析 `>` 开头的六轴角度及可选速度参数 |
| `0x08012B2C` | 七参数路径：速度限制在 0～100，与 `+0x154` 系数相乘，保存到 `+0x150` |
| `0x08012B7A` | 调用 `0x08011A34`，其行为对应 MoveJ |
| `0x08011B38` | 计算目标减去 `+0x54` 的六轴当前角度 |
| `0x08011B54` | 从六个绝对差值中选最大值及其轴号 |
| `0x08011C0C` | 读取最大差值轴的减速比，以及公共速度 |
| `0x08011C2A` | 计算 `1 / (最大角度差 × 对应减速比)`，没有零分母分支 |
| `0x08011C36` | 公共速度乘 float32 常量 0.1 |
| `0x08011C6E`～`0x08011D16` | 各轴差值乘各自减速比、公共速度与比例，取绝对值，分别存储六轴速度 |
| `0x080119FC` | 遍历六轴，将各自位置与速度传给底层电机函数 |
| `0x0800FCD8` | 转换位置的方向、减速比及圈数，速度原样放入 CAN 数据后四字节，命令号 0x07 |

命名由行为和源码交叉识别，不来自实机 ELF 调试符号。

设 `d_i = 目标角_i - 当前角_i`，`R_i` 为对应减速比，`m` 为绝对角度差最大的轴，
`S` 为公共参数，`k` 为模式系数，则非零位移时实际代码等价于：

```text
V_i = |d_i| × R_i × clamp(S, 0, 100) × k × 0.1 / (|d_m| × R_m)
```

`V_i` 是主控下发到驱动板的位置＋速度消息中的速度字段，不是本次测得的机械速度。
参考驱动协议按电机圈/秒解释该字段，但本次没有读取各独立驱动板固件，不能据此
宣称已经实测各轴速度、加速度或负载跟随能力。

例如 `S=16、k=1`，J1 差 2°、J4 差 8°，其余轴差 0°；两轴减速比均为 50：
J1 速度字段 0.4，J4 为 1.6，分配比例 1:4。
如果两轴误差同时翻倍为 4°、16°，分配仍是 0.4、1.6。
因此它是按各轴相对行程进行协调，并非总误差越大就无限增加速度的固定比例控制器。

## 当前 RAM 只读核对

机器人对象基址 `0x200035A8`；Flash 中存在 13 处对此全局地址的对齐引用，
其六轴对象节点号依次为 1～6。

| 数据 | 地址／偏移 | 本次读数 |
| --- | --- | --- |
| 模式 | 对象 `+0xDD` | 2 |
| 公共速度 | `0x200036F8`，对象 `+0x150` | 16.0 |
| 速度系数 | `0x200036FC`，对象 `+0x154` | 1.0 |
| 六轴减速比 | 电机对象 `+0x19` | 50、50、50、50、50、30 |
| 使能标志 | `0x2000371C`，对象 `+0x174` | 0，未使能 |
| 六轴分配速度缓存 | `0x20003700`～`0x20003714` | 六项均为 `0x7FC00000`，NaN |

运行内存不是原子快照；随后独立 HotPlug `-r32` 再读速度区、`-r8` 再读使能标志，
仍为 16、1、六个 NaN、未使能。六个电机对象的 CAN 发送数据缓存中速度字段也均为 NaN。
这只能证明主控缓存的内容，不能证明驱动板此时的状态或当时是否已接收该帧。

## 额外发现：零位移速度计算缺陷

当六轴目标与参与本次计算的六轴反馈全部相等时，最大差值为 0，实机指令执行
`1/0` 后再乘零差值，会得到 NaN，且未在保存六轴速度前过滤。
`0x080126B4` 的停止处理路径读取六轴当前角度并在 `0x080126D4` 调用同一 MoveJ，
随后调用位置＋速度下发函数，因而存在进入上述零位移计算的路径。

“零分母路径存在”及“本次速度缓存确实为 NaN”已确认；它与停止时形成缓存的解释
相符，但缺少触发瞬间记录，不能断言本次 NaN 一定在某一条停止命令产生。
也不能凭失能后的缓存证明此前运动一直使用 NaN，或把卡顿、8° 超差全部归因于它。
本轮没有修改或烧录此处固件。
