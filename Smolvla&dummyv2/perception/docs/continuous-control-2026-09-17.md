# 连续目标推进验证（0.8.0）

## 问题与实现

原先 Servo 的每个位置小步都基于实测关节角。硬件读取降到 5 Hz 后，同一反馈
可用于多个 40 Hz 周期，造成重复发送接近相同的目标；提高发送次数不能使这些
目标变成连续轨迹。

改为 Servo 输出六轴速度，由网关每周期累积位置目标，使用最近真实反馈约束
最大超前 6°，并遵守各轴限位。各轴共同缩放新增位移，超出部分丢弃，不积压。
采样仍为 5 Hz；目标不会写回 joint_states 充当实测状态。

速度转换只有弧度到角度及各轴方向，不包含 J3 的位置偏置。松键、失能、输入
超时、反馈过期、碰撞停止都清除累积。调度间隔超过 100 ms 时不积分缺失时间；
新目标缺失超过 250 ms 则暂停。重新按键允许有限的首帧等待，不误用上一轮目标。

生产协议升为 4；反馈提交同时返回轨迹快照，每周期少一次 HTTP 查询。
平移 0.1 m/s、转向 0.24 rad/s、主控速度参数 8 不变，没有改固件、桥接或原工作区。

MoveIt 数据契约参考官方 Jazzy 源码：
[Servo 节点](https://github.com/moveit/moveit2/blob/jazzy/moveit_ros/moveit_servo/src/servo_node.cpp)、
[MultiArray 组包](https://github.com/moveit/moveit2/blob/jazzy/moveit_ros/moveit_servo/src/utils/common.cpp)。

## 验证

- Windows 自动测试 214 项通过，包括共享反馈、速度转换、两次采样间连续推进、
  饱和与反向无积压、限位、失效清除、首帧等待超时和原有动作保护。
- `verify_control_loop.py` 使用真实 MoveIt、隔离 ROS domain 196、模拟 USB 控制器，
  不访问实机。模拟电机最大跟随速度为 60°/s，读取 5 Hz。
- W、A、上、下、转向各运行 1.5 秒，分别产生 53、26、19、21、49 个不同目标；
  均持续移动。对应总下发为 53、49、48、49、55 次。限幅时允许目标重复。
- 松键后只发送保持目标；模拟卡住触发 `motion_no_progress` 并保持使能；加入
  覆盖机器人的模拟障碍后，碰撞状态 5 能暂停控制。
- 此次运行目标相对最新反馈最大差约 6°；报告保存在
  `runtime/control-loop-offline.json`，完整输出在离线测试日志中。

## 限制

40 Hz 是设定周期，不是实机成功下发频率保证；测试使用本机直接调用网关和模拟
串口，不能代表 Windows/WSL HTTP、真实 USB 或 MCU 的时延，也未验证实物手感。
5 Hz 反馈仍限制真实状态更新速度，达到 6° 超前限制时会等待后续反馈；碰撞检测
使用实测姿态，不等于对整个超前目标段做连续碰撞验证。
6° 限制相对最后一个有效样本，不能保证与未采样的瞬时物理姿态始终相差不超过 6°。
原主控异常的 5 Hz 查询缓解措施继续保留，本次改动不宣称修复 MCU HardFault。
