# 22:44 停止输入时反馈丢失

事务 36900 的最后运动确认仍为 `15\r\nok\r\n`，3.07 ms 返回。
随后 36902 的 GETJPOS 回复含 NUL 字节，且没有换行：

```
ok 2.31 0.05 \x00\x00.\x004 -2.30 45.09 3.18
```

反馈校验正确拒绝了该帧；复读事务 36904 等待 4.54 秒后失败
`worker_unavailable: local_worker_deadline`，后续重新打开 COM7 被拒绝。
六轴 STOP、DISABLE 和夹爪 DISABLE 都未能发送。此次日志中未收到上一故障的
`terminate called...`，不能把两次故障直接断定为相同 MCU 异常。

上层 `hold_stream()` 将 `read_state()` 返回的 `positions=None` 传给目标验证器，
导致误报“MoveIt 必须返回六个有限关节角”。0.7.5 修复该错误链：
读取与保持发送在同一 IO 锁内；无有效反馈直接返回 503
`hold_feedback_unavailable`，保留通信原因，不向目标验证器传空值，
不使用旧反馈或零角度替代，控制仍执行故障退出及急停尝试。

187 项 Python 测试通过，包含从日志提取的空字节回复、随后通信失败的完整停止输入路径，
以及单个坏帧复读成功后只使用新角度保持的场景。

此修改解决错误归因及空目标传递，不修复底层串口失联。需要继续检查设备故障现场、
USB 链路和实机固件；没有完整异常类型或 MCU 现场，不断言为内存不足、堆损坏或线缆故障。
原始日志保存于 `runtime/feedback-fault-20260916-224442/`。
