# 0.7.7：进入实机控制失败与准备位速度

用户确认故障是长按进入实机控制失败，不是急停按钮无法触发。

## 原因与证据

0.7.6 新增真实反馈帧龄传递后，旧初始化顺序存在确定的时序缺陷：
先取角度 -> 检查网关 -> `#CMDMODE 2` -> 将先前角度交给网关 -> 请求进入控制。

桥接日志的事务 101793/101794、101821/101822、101919/101920 显示，
模式切换命令均得到 `ok Set command mode to [2]`，但事务分别耗时
501.14、501.0、500.85 ms。传递先前角度时帧龄已超过网关 500 ms 限值，
因此会被判定过期。服务日志显示用户多次 `/api/control/arm` 返回 503。
原实现没有记录网关的具体失败原因；不能声称已经保存了每次 503 的原始响应体。

修复在模式切换完成后重新调用共享读取，再验证并转发最新有效反馈。
若读取失败仍拒绝进入，不放宽帧龄阈值，不继续使用原先角度。
网关进入控制失败时记录 `arm_failed` 事件并在错误信息中保留具体原因。

## 准备位速度

`ready` 的主控速度参数从 4 改为 8；`home`、`rest` 仍为 4。
动作状态、实际下发与超时预算统一从 PRESET_SPEEDS 读取，网页使用动作返回速度显示。
加减速和负载影响实际到位耗时，速度参数翻倍不代表总耗时精确减半。

## 验证

196 项 Python 测试通过；键鼠／长按页面事件测试通过。
新增回归模拟 501 ms 模式切换：确认在切换后重读角度，网关收到新位置及帧龄 0，
进入控制不发送关节运动目标。另验证重读失败时不进入网关控制、不复用旧角度。
准备位测试断言实际下发速度 8，其他预设速度仍为 4。

本轮没有自动执行真机准备位或键鼠运动；真实运动速度由现场用户验收。
