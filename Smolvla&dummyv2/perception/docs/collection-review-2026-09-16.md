# 数据采集模式 0.6.0 验证

## 原因和修复

之前的控制器把 Servo 轨迹末尾状态继续作为下一轮规划起点，而桥接每次运动命令
等待约 500 ms。这会使计划目标领先实际机器人，静止的模拟实机也会出现十几度的
累积目标，最终触发 4° 检查。现在使用基于当前反馈的直接位置输出，周期 100 ms，
完整运动确认到达后立即释放串口。没有放大 4° 目标差保护，也没有改动固件或原始
dummy_moveit_ws。

此行为依据 MoveIt Jazzy 的
[servoLoop 实现](https://github.com/moveit/moveit2/blob/jazzy/moveit_ros/moveit_servo/src/servo_node.cpp)：
JointTrajectory 模式可使用滚动窗口里的命令状态，直接位置数组模式使用关节反馈。

其他问题包括：两个网页会互相覆盖控制输入，中心附近鼠标细小偏差持续产生转动，
松键仅停止产生新轨迹而未替换已发送目标，以及退出后仍显示旧的 sending_target。
本版增加页面所有权、中心静止区、一次保持目标、输入代次检查和明确的退出诊断。

## 已执行的隔离验证

- 134 项 Python 自动测试通过，覆盖串口分段确认、使能锁存、保持、断线、录制与配置等。
- `motion/probe_servo_offline.py`：实际 Servo 配合静止反馈持续 4 秒，最大目标差约
  0.892°，未随时间增长；折叠奇异位仍产生停止警告。
- `motion/verify_control_loop.py`：实际 Servo + 网关 + 生产 LiveControl/RobotClient，
  假机器人反馈速度上限 4°/s、反馈 5 Hz；W、A、鼠标转向都有运动，松键后无持续
  位移；卡住 3 秒暂停，仍保持会话；两轮最大目标差均低于 0.94°。报告在
  `runtime/control-loop-offline.json`。这些数值是离线模拟结果，不是实机运动测量。
- `tests/ui_collect_review.cjs`：Playwright 在 1440×900、390×844 验证键盘输入、
  长按进入、鼠标静止区、右键夹爪停止、文本输入不驱动、双页面隔离、无横向溢出
  和按钮重叠。所有 API 都由假服务处理，三路图像使用测试图片。
- 录制操作移至页面上方，显示帧计数、磁盘剩余空间和不完整片段原因；深度尺寸使用
  实际深度流数据，过期画面不会继续显示为正常。

## 实机只读观察与剩余边界

上方 RGB 能看到机械臂、显示器和邻近线缆；图像不能证明整个运动范围无障碍。
重启前 OAK 报告 USB2（HIGH）、1280×720 时实测约 16 FPS；重启后按当前保存配置
640×360 运行，实测约 30 FPS，腕部约 30 FPS。页面提示 USB2 连接及实测帧率。
机械臂不会因服务重启自动进入实机控制。进入控制后 `#CMDMODE 2` 的真实确认以及
修复后的运动手感仍需操作人员在场验收；此轮没有发送实机运动或自动使能命令。

夹爪点动保持既有方向/电流命令，默认 0.60 A；没有重新启用 HAND_POS。
夹爪角度的 ST-LINK 读取目前不可用，因此不能将其记录视为完整的夹爪角度训练标签。
当前录制包含真实相机帧、关节样本和事件，但尚不是 LeRobot/SmolVLA 训练数据格式。
